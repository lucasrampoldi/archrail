## ADDED Requirements

### Requirement: Sync renders active standards into agent context

`archrail sync` SHALL resolve the project's adopted architecture profile (see architecture-profiles) and render that profile's validated standards into agent-consumable context. The rendered context MUST be human-readable, MUST identify the adopted profile name and version, and MUST faithfully represent every active rule's `id`, `description`, `severity`, and the intent of its constraint. Sync MUST validate the resolved profile first and MUST refuse to render if it cannot be resolved or is invalid.

#### Scenario: Sync produces context for valid standards

- **WHEN** `archrail sync` runs against a valid `.archrail/` directory
- **THEN** it SHALL write the rendered context and exit zero

#### Scenario: Sync refuses invalid standards

- **WHEN** `archrail sync` runs against standards that fail validation
- **THEN** it SHALL not write any output, SHALL report the validation error, and SHALL exit non-zero

### Requirement: ARCHRAIL.md is the canonical adapter

Archrail SHALL provide an `ARCHRAIL.md` adapter as the canonical, default sync target, written to the repository root. The generated `ARCHRAIL.md` MUST be deterministic (stable ordering, stable formatting) so re-running sync with unchanged standards produces no diff, and MUST clearly mark the file as generated by Archrail.

#### Scenario: Deterministic regeneration

- **WHEN** `archrail sync` is run twice with unchanged standards
- **THEN** the second run SHALL leave `ARCHRAIL.md` byte-identical to the first

#### Scenario: Generated marker present

- **WHEN** `ARCHRAIL.md` is generated
- **THEN** it SHALL contain a marker identifying it as Archrail-generated and warning that manual edits will be overwritten

### Requirement: Pluggable adapter abstraction

Sync SHALL route output through an **adapter** abstraction so that additional agent- or tool-specific targets can be added later without changing the standards format. v0 MUST implement only the `ARCHRAIL.md` adapter but MUST allow the adapter to be selected by name, defaulting to `ARCHRAIL.md`.

#### Scenario: Default adapter selected

- **WHEN** `archrail sync` is run without specifying an adapter
- **THEN** the `ARCHRAIL.md` adapter SHALL be used

#### Scenario: Unknown adapter requested

- **WHEN** `archrail sync` is run with an adapter name that is not registered
- **THEN** Archrail SHALL exit non-zero and list the available adapters

### Requirement: Drift detection for generated context

`archrail sync` SHALL support a check mode (e.g., `--check`) that reports whether the on-disk generated context is up to date with the active standards without writing changes, so CI can enforce that `ARCHRAIL.md` was regenerated.

#### Scenario: Stale generated context detected in check mode

- **WHEN** `archrail sync --check` runs and the on-disk `ARCHRAIL.md` differs from freshly rendered output
- **THEN** Archrail SHALL exit non-zero and report that the generated context is stale

#### Scenario: Up-to-date generated context passes check mode

- **WHEN** `archrail sync --check` runs and the on-disk `ARCHRAIL.md` matches freshly rendered output
- **THEN** Archrail SHALL exit zero and write nothing
